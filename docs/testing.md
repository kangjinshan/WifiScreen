# 验证说明

## 单元测试

```bash
cd android
./gradlew :app:testDebugUnitTest :app:lintRelease
```

当前 118 项单元测试覆盖 RTSP / RTP、AVC 配置与边界、关键帧处理、旧发送端所需的响应头格式、UTF-8 内容长度、解码消费者变慢时保留帧顺序和正常停止，以及连续 PCM 原样播放、音画时间映射、时钟切换、有界显示调度和画面修复。

## 0.2.9 颜色诊断与画面修复回归

- 独立 libx264 参数集覆盖 BT.709 limited、BT.2020/PQ full 和未指定颜色；用 ffprobe 核对原始测试码流信令。覆盖 High profile、转义字节、截断输入、未知 PPS、隔行、FMO 和辅助图像 NAL，解析失败不改写输入。
- 使用一个图像的多个分片验证：首片到达不能重建，后续分片不能被当成完整图像，下一图像首片确认边界后只重建一次。确认保留的 IDR 整帧合并，分片顺序和字节不变。
- 验证静止画面、没有新 IDR、参数变化、分片顺序不合法、候选超过数量/字节上限、重复点击、30 秒冷却、验证超时、停止与不可重复启动。超时不释放原有解码器，不清空音频或断开连接。
- 验证诊断历史最多 32 条、旧快照不会随新事件变化、长时间年龄使用 Long、重复配置不虚增版本、未知颜色保持未知。
- 模拟器通过真实遥控器路径触发修复，核对源/输出颜色字段、重建次数、同一会话持续、音频播放头推进、修复前文件在重连/进程重启后保留，以及冷却拒绝不覆盖文件。
- 音频样本核对使用「解码样本 + 已确认缺口的补偿样本 - 重叠样本」，另行记录真实丢包和欠载。不能把模拟器运行时的网络丢包误当作修复修改音频。
- 继续执行单 IDR 突发、重复配置和横竖屏回归。硬件可能对逐 NAL 输入给出不同的输出计数；确认首帧完整与颜色需检查图像，不能用 decoded/presented 计数代替。
- 目标极米没有 ADB，模拟器检查不能证明该投影长时间偏红已根治。实机还需检查完整关键帧到达率、修复前后颜色、声音连续性与至少两小时运行。

## Release 工作流回归

在仓库根目录运行 `python3 -m unittest discover -s tests -p test_release_workflow.py -v`。测试直接执行工作流内的发布逻辑，模拟首次发布、重复发布、产物不全、源码或签名不一致，以及 GitHub API 失败；不会访问或修改线上 Release。已有版本重试还需在 Actions 中选择最新 `main` 工作流并填写 `release_tag`，以验证旧标签源码与最新发布逻辑的组合。

## 视频回归

使用合成 H.264 测试画面通过真实接收 TCP 路径验证，不采集用户画面：

- 横屏与竖屏各 90 帧，核对输出帧数和比例。
- 180 帧突发输入，只有第一帧为 IDR，期间重复发送相同 AVC 配置。0.1.2 可重现只输出 1 帧的错误；0.1.3 保持所有 180 帧顺序并完整输出。
- 验证应用退到后台会停止网络服务，再打开使用相同固定端口及设备身份。
- 读取 `/diagnostics`，确认固定地址与版本正确，无需随机验证码。

## 实机验收

接收目标为极米 Z6X / Android 9；发送端包括小米与 Redmi 系统投屏。已确认平台硬件 AVC 解码器 `OMX.MS.AVC.Decoder` 输出 1920×1080 画面，AAC-ELD 音频解码后由 AudioTrack 播放。

长时间测试应同时检查 `videoReceived`、`videoDecoded`、`videoOutputAgeMs` 与音频计数。仅看到连接状态或声音持续，不能判定画面一直正常。手机画面静止时可能降低帧率，应结合 `videoQueueDepth` 与实际显示确认。

模拟器广播名称为 `WifiScreen Emulator Test`，实机为 `WifiScreen 投影`，避免名称冲突。联调结束应退出模拟器接收应用，清理测试用端口转发。

## 0.2.2 音频时钟兼容回归

- 单元测试覆盖非样本时间戳单位、字节序不同、时间戳跳变与常量、序号回绕、缺包时长，以及抖动估计和 SSRC 切换。
- 使用相同的合成 AAC-ELD 音频对比新旧 APK：旧版异常时间戳会逐帧重置、无法完成启动缓冲；新版应无重复重置，`audioPlaying` 为真且 `audioPlayedFrames` 持续增长。
- 分别用标准与异常时间戳发送有意缺包、乱序和重复包，检查短缺口保留时长、重复包不重播、无队列溢出，视频持续输出。
- 保持系统原有缓冲与额外 20ms 策略。模拟器播放头推进不能替代 Redmi 到目标投影的声音和口型同步验收。

## 0.2.3 视频积压追帧回归

- 先突发送入 32 帧，再持续发送 30fps，模拟已有约一秒积压。使用单个 IDR 和后续相依帧验证：旧版持续落后约 32 帧；新版应追到队列尾部，仍完整解码所有帧。
- 检查积压时的显示决策不增加等待、长期追帧仍有过渡画面、追上后恢复正常时间戳节奏，以及 OEM 常量输出时间戳不会重新强制等待。
- 用突发视频和重复配置检查参考帧完整性；结合合成 AAC-ELD 检查视频追帧后声音正常启动、播放头推进与缺包补偿。
- `videoReceiverLatencyMs` 仅用于接收端内部耗时比较，不当作手机到投影的端到端延迟。
- 音视频合测曾记录音频欠载，使用相同条件的 0.2.2 基线也可复现；不能据此宣称零卡顿，实机声音仍需复测。

本地设备 IP、序列号、原始日志、研究文件和签名凭据不放入公开仓库。

## 0.2.4 音频连续性与同步回归

- 合成波形检查短缺口的能量、声道相位、接续边界与时长，正常 PCM 和静音输入保持原样。
- 验证每次连续缺数据的补偿上限、约 5ms 临时补音、迟到 PCM 不重复播放，以及新包正常到达时不会把批量解码误判为缺口。
- 验证长缺口保留 AudioTrack，视频在实际播放进度到达接续点时再跳过对应区间；排队写入本身不提前触发跳时。
- 覆盖时钟回绕、长时运行、音频停滞、空缓冲恢复、独立重置与常量视频时间戳回退。
- 模拟器通过真实 UDP/AAC/AudioTrack 与 TCP/H.264 链路分别测试正常、短丢包、长丢包和迟到包，核对写入样本等于解码样本减去重叠样本再加补偿样本。额外等待预算仍为 20ms，视频参考帧与原帧率保留。
- 零欠载检查与功能检查分开记录；实机仍需确认声音、口型同步和端到端延迟。

## 0.2.5 杂音与错误追帧回归

- 模拟每两包成组到达且无丢包的音频流，对比旧版的预测补音计数。新版必须满足 `audioConcealedSamples=0`、`audioStarvationSamples=0`、`audioOverlapSamples=0`，PCM 写入样本与解码样本完全相同。
- 对实际缺失一包或多包的情况，验证短缺口补偿、长缺口接续仍正常，且不会重建 AudioTrack。
- 单元测试使用独立副本核对正常 PCM 与变长批量输入逐字节不变，避免同一数组被原地修改掩盖回归。
- 模拟一幅画面的四个输入分片、硬件省略输出和不同输出顺序，核对时间记录有界、不会累积假队列，也不会因输入时间戳重复而关闭音频同步。
- 重用低延迟追帧和单关键帧突发视频回归，保留原画质及参考数据。原样播放检查和播放设备的零欠载检查分别验收。

## 0.2.6 异常时钟卡画面回归

- 模拟视频时间戳未跟随长时间停发推进、音频持续播放，验证大负差回退，不会一直丢弃新画面；正常范围内的负差仍支持同步。
- 通过真实接收链路暂停视频发送 3 秒，随后以原媒体时间戳恢复，音频保持连续。比较旧版恢复后全部丢显示与新版继续显示的行为，保留同一个关键帧及所有解码参考数据。
- 继续验证突发视频、实际积压追帧以及无丢包时音频不被补偿或替换。

## 0.2.7 帧率与显示调度回归

- 调度单测覆盖等待显示期间接收后续输出、连续 30fps 与未来显示时间重叠、缓冲容量、输入压力释放、单帧持有上限，以及停止时每个输出只回收一次。
- 用 1080p / 30fps 合成视频与 AAC-ELD 连续输入，核对 `videoPresented` 的稳定区间增量，并读取 SurfaceFlinger 实际呈现时间，避免只用解码计数判定帧率。
- 验证最多 4 个待显示输出，保留正常 PCM、暂停恢复、异常时钟回退和单关键帧突发输入的参考数据完整性。
- 模拟器数据不能代替目标投影的 30fps 验收。提前显示次数和音画同步听感需一起观察；原生音频欠载仍单独记录。

## 0.2.8 显示延迟与时钟切换回归

- 时钟单测比较同一时刻的位置，覆盖时间戳间歇失效、硬件源接入、保留偏移的回退、渐进校正、空缓冲、采样停滞和重启。时钟尚未稳定时视频必须继续独立播放。
- 模拟持续 30fps 且音频显示目标落后 180ms，检查每帧在 20ms 应用等待预算到达后释放，正常待显示队列不积累为 4 帧。突发时仍验证输出所有权和参考数据完整性。
- 短暂时间偏差不能丢弃正常画面；持续迟到需要已有解码替代画面；确认的音频跳过区间继续联动视频。
- 使用同一台模拟器、相同 1080p30 与 AAC-ELD 成对输入，对比 0.2.3、0.2.7 和 0.2.8。记录延迟中位数/P95、实际显示 FPS、SurfaceFlinger 呈现、时钟切换、提前释放和音频欠载，保留所有轮次的波动。
- 音频连续输入须保持 PCM 样本数不变；继续执行暂停恢复、单 IDR 积压追帧和重复配置突发回归。低延迟音频模式需读取实际模式，不能把请求成功当作设备已启用。
- 限制显示等待可能使画面领先较慢的声音输出。目标投影上的完整延迟、声音连续性和口型同步仍需同场景验收。

## 实时速率显示回归

- 使用遥控器方向键聚焦「显示实时速率」，确认键切换，重启应用后保留设置。
- 开启后分别发送横屏、竖屏合成视频，检查绿色 FPS 与 KB/s、MB/s 位于实际视频区域左上角。
- 暂停发送但保持连接，待队列排空后应显示零速率；断开后返回首页并隐藏统计。
- 关闭开关后再次投屏，确认视频正常播放且没有统计叠层。FPS 不包括跳过显示的帧，速度包含音视频接收数据。


## 20ms音频回归

使用合成 AAC-ELD（44.1kHz、双声道、每包480样本）同时发送H.264视频，检查完整PCM输出、RTP乱序恢复、重复包过滤和播放中的AudioTrack欠载。测试也覆盖RTP序号/时间戳回绕、时钟重启、短缺口时长保留、视频启动延迟及持续时钟偏移恢复。物理设备上的听感与口型同步仍需实机观察，计数器不能代替听觉验证。

## 0.2.0 影院界面与连接恢复回归

- 名称校验覆盖 UTF-8 字节上限、空白、特殊字符和协议 XML 转义。
- 画面几何覆盖竖屏完整显示、铺满裁切、手动移动边界和异常设置归一化。
- 卡顿检测覆盖静止画面、持续积压、恢复解码、新会话以及首帧等待超时。
- Android TV 模拟器中用真实遥控器按键路径验证名称编辑、设置保存、菜单返回、静音、画面调整、横竖屏切换和确认结束。合成视频通过真实 TCP 接收与 MediaCodec 显示路径，不使用用户画面。
- 在测试模拟器上关闭并恢复 Wi-Fi，核对未连接提示、自动重新发布、名称与设备身份保持不变。测试完成后恢复模拟器网络。
- 这些检查不能替代目标投影仪的遥控器、画面边缘和音画听感验收。

- 首页三个按钮通过截图像素边界核对文字中心与按钮中心，误差低于 2 个物理像素；图标不参与文字居中计算。
