# 验证说明

## 单元测试

```bash
cd android
./gradlew :app:testDebugUnitTest :app:lintRelease
```

当前 40 项单元测试覆盖 RTSP / RTP、AVC 配置与边界、关键帧处理、旧发送端所需的响应头格式、UTF-8 内容长度、解码消费者变慢时保留帧顺序和正常停止，以及实时速率采样的计时偏差、静止画面和重连重置。

## Release 工作流回归

在仓库根目录运行 `python3 -m unittest discover -s tests -p test_release_workflow.py -v`。测试直接执行工作流内的发布逻辑，模拟首次发布、重复发布、产物不全、源码或签名不一致，以及 GitHub API 失败；不会访问或修改线上 Release。已有版本重试还需在 Actions 中选择最新 `main` 工作流并填写 `release_tag`，以验证旧标签源码与最新发布逻辑的组合。

## 视频回归

使用合成 H.264 测试画面通过真实接收 TCP 路径验证，不采集用户画面：

- 横屏与竖屏各 90 帧，核对输出帧数和比例。
- 180 帧突发输入，只有第一帧为 IDR，期间重复发送相同 AVC 配置。0.1.2 可重现只输出 1 帧的错误；0.1.3 保持所有 180 帧顺序并完整输出。
- 验证应用退到后台会停止网络服务，再打开使用相同固定端口及设备身份。
- 读取 `/diagnostics`，确认固定地址与版本正确，无需随机验证码。

## 实机验收

接收目标为极米 Z6X / Android 9；发送端包括小米与 Redmi 系统投屏。已确认平台硬件 AVC 解码器 `OMX.MS.AVC.Decoder` 输出 1920×1080 画面，AAC-ELD 音频解码后由 AudioTrack 播放。

长时间测试应同时检查 `videoReceived`、`videoDecoded`、`videoOutputAgeMs` 与音频计数。仅看到连接状态或声音持续，不能判定画面一直正常。手机画面静止时可能降低帧率，应结合 `videoQueueDepth` 与实际显示确认。

模拟器广播名称为 `WifiScreen Emulator Test`，实机为 `WifiScreen 投影`，避免名称冲突。联调结束应退出模拟器接收应用，清理测试用端口转发。

本地设备 IP、序列号、原始日志、研究文件和签名凭据不放入公开仓库。

## 实时速率显示回归

- 使用遥控器方向键聚焦「显示实时速率」，确认键切换，重启应用后保留设置。
- 开启后分别发送横屏、竖屏合成视频，检查绿色 FPS 与 KB/s、MB/s 位于实际视频区域左上角。
- 暂停发送但保持连接，待队列排空后应显示零速率；断开后返回首页并隐藏统计。
- 关闭开关后再次投屏，确认视频正常播放且没有统计叠层。FPS 不包括跳过显示的帧，速度包含音视频接收数据。


## 20ms音频回归

使用合成 AAC-ELD（44.1kHz、双声道、每包480样本）同时发送H.264视频，检查完整PCM输出、RTP乱序恢复、重复包过滤和播放中的AudioTrack欠载。测试也覆盖RTP序号/时间戳回绕、时钟重启、短缺口时长保留、视频启动延迟及持续时钟偏移恢复。物理设备上的听感与口型同步仍需实机观察，计数器不能代替听觉验证。
